# 关闭程序自动跟随后手选模板被清除

- 发现日期：2026-10-04；实现与验证跨至 2026-10-05。
- 状态：等待真机验证。
- 影响范围：本地 0.5.0 Windows 候选的公共模板状态机；不以当前测试外推 RC001/RC003 全部实体按键。
- 功能点：菜单手选、按键页当前模板、模板页实际高亮。
- 现象：关闭“按程序加载默认模板”后，菜单选中模板不能稳定改变后续按键行为。
- 复现条件：关闭自动跟随，菜单确认模板，再切换外部程序或丢失前台身份；原状态机清空手选并回通用。旧测试 `temporary_selection_still_expires_when_program_defaults_disabled` 曾固定此错误契约。
- 正常预期：开关仅控制按程序自动选择；关闭时手选在本次进程内保留，三个入口共享实际映射状态。
- 证据：实际配置只读核对已有模板与程序关联、自动/菜单开关有效；现场未保留可完整重放该模板失败的历史动作日志，未以此前驻留 Agent 故障代替本次根因。新增四个场景测试在旧实现上按预期失败，随后通过；映射工作线程记录真实消费动作，详见测试专项。
- 根因：`manual_application_id` 无条件限制手选生存期，前台变化/不可用和菜单关闭会清空；冷启动还要求外部 token。前端编辑目标与当前执行目标概念不同，模板页缺少 applied 订阅。
- 修复：统一进程内手选与启用跟随时的程序覆盖规则；按钮选择等待实际映射确认，超时/取消/退出按新代回滚；前端只消费 applied notice/revision，不把草稿或候选当当前。保存默认关联仍走原显式确认，不新增配置迁移或手选持久化。
- 验证：场景 46 项、前端 255 项、Rust 工作区/check/fmt 通过；模拟边沿 + 实际映射工作线程记录 `A→B→B→A→C`。独立复查还发现旧回调可能晚于新确认提交旧映射；可控交错先实证 UI 为 B 而真实执行 A，再通过串行读取/提交使实际执行 B；最终计数与实机边界归 [模板专项](../Testing/StructuredTemplatesAndDrivers.md#2026-10-0405-手动当前模板与三入口同步)。实体菜单、跨页面高亮与实际遥控器输出 `deferred`，不以录制注入器替代。
- 隐私检查：没有端点身份、程序路径、窗口内容、语音或凭据。

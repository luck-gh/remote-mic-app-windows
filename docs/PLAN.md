# 项目方向与计划入口

## 目标与当前阶段

无线麦 SayAll Windows 版面向小米蓝牙遥控器 2 / RC001 和 2 Pro / RC003，提供按住说话与按键映射。产品范围、普通用户权限、公开 API、语音生命周期和平台分层约束由根目录 [AGENTS.md](../AGENTS.md) 定义；架构选择见 [ADR 0001](decisions/0001-tauri-rust-windows-only.md)。

当前处于产品化与分场景验收阶段。代码已形成 Vue 页面 → Tauri IPC → Windows 平台层 → 纯 Rust 语音管线的纵向路径；当前可证明的行为及其验证范围见 [FEATURES.md](FEATURES.md)。代码存在、自动化通过与双型号真机通过分别判断。

## 当前范围调整：模板统一按键映射（2026-09-22 用户纠偏）

用户明确要求所有内置与用户模板只发送固定键或组合键，删除第三方区域分类、UIA 能力扫描及语义动作队列，不能只绕过按键执行却继续后台扫描。程序只通过公开进程身份匹配一个默认模板，同程序不同窗口不重选、不重复提示；未匹配或关闭程序默认跟随时使用通用配置。

遥控 Menu 保留本应用完整模板菜单。“同时更新此程序的默认模板”记录上次选择并在重开/应用重启后恢复（2026-09-22后续用户纠正原每次不勾选设计）；取消菜单保留这个偏好，只有确认模板才改变程序关联。未勾选时临时选择仅当前程序本次前台使用期有效，切到其他外部程序后清除；本应用菜单/主窗口不算外部切换。勾选则在最新配置锁内只更新打开菜单时捕获程序的单条默认关联；成功才显示已更新，失败明确提示且保留临时选择。公开窗口身份、菜单循环/滚动/确认真实 UP 与焦点恢复、实际 applied 短提示、来源/原生抑制及按住释放配对继续保留。

一次现有配置转换保留用户模板 ID/名称、直接动作与缺项、程序关联及其他偏好；仅按原输入区的无歧义固定键转换，确认长按发送、Home/TV 聚焦和旧长 Menu 调节等无固定等价项置为未配置。原始配置只留受限本机恢复依据，不保留可运行的旧语义兼容或扫描开关。任务状态归 TODO，转换/安装/实测证据归既有三键 evidence；旧未返回的冷态语义验收不再执行，不记 passed。电源与无线电试验仍禁止。

同日用户补充：仅完整模板面板内长按Menu可切换“同时更新此程序的默认模板”，每个物理长按一次，释放不再短按取消；短Menu/返回取消。切换记录保存意图，确认模板才保存原目标程序默认；取消不撤销偏好。复用已有手势识别，不向用户按键模板添加Long动作或新时序设置。

## 当前范围调整：三键宿主 HID 旁路（2026-09-15 用户确认）

用户在已获知参考程序使用 Frida 注入 WUDFHost、私有 IOCTL 与原规则冲突后，明确要求：“按照这个新项目的参考思路，能对咱们当前无线麦这个项目进行改良，能对这3个按键的功能进行增加”。因此，仅返回、音量加、音量减的可选增强允许使用指定遥控器 Windows HID 宿主的旁路观察，作为 AGENTS 公开 API/协议边界的限定例外；不扩大为语音依赖、第三方输入法注入、任意进程或任意脚本能力。

主程序保持普通权限，附加由独立显式 UAC Helper 承担；仅接受本地活动用户会话及已确认设备，保留安全设置。不得自动修改 Defender 排除、Secure Boot、内存完整性或签名强制。优先官方固定版本 Frida core 的脚本卸载/Session detach，不能以 socket 关闭或 API 返回成功代替撤钩、边沿释放或模块卸载实证。先核只读报告、同步/异步完成、设备归属和系统原生消费；未确认抑制需求前不改系统报告、不新增全局吞键。RC003 先取得实体证据，RC001 不凭共有 VID/PID 外推。历史 KMDF 候选的编译和未签名事实保持，是否替代由实际旁路证据判断，不预先移除有效源码。

同日用户进一步要求实体键盘与遥控器同时正常使用。本项同时覆盖遥控器 TV/Home 的精确设备来源与单次映射；明确撤销旧“Home/反引号低频，遥控器在线可接管键盘”取舍。来源未确认前，不得以相同 VK、遥控器在线、最近使用或四秒武装窗口吞下可能来自实体键盘的事件。保留遥控器 TV/Home 映射且不出现原生加映射双响应；实体反引号、Shift+反引号、Home 及组合正常，按住、重复、交替/同时、断连、睡眠、退出均成对。限定宿主旁路例外因此扩展到这些指定遥控按键的设备区分，不扩展语音或第三方进程范围。单纯删除常驻抑制而留下武装误吞/原生泄漏，不构成完成。

本项验收状态仍归 TODO，固定来源与许可归 ATTRIBUTION；本节是该例外的唯一决策真源。配置不因安装或启动自动启用增强，实际宿主操作须使用可审查候选和明确范围。

2026-09-15 实证已否定把所选 PDO 名称直接等同宿主 IOCTL file object 的当前假设：真实按键对照存在，归属门仍无命中。后续方案必须给出逐设备来源闭环，不能把同宿主、名称前缀或按键时序作为授权。现有只读实验到此收束，不自动追加附加/重连实验；是否继续新的可审关联方案或正式签名驱动路线需基于具体方案决定，不以源码审查或安装 UI 代替验收。证据归 `artifacts/hid-host-three-key-20260915/evidence.md`。
2026-09-19 用户明确要求先保存已完善功能、再继续三键开发。本轮后续方案限定一次 future-open 元数据验证：只从公开 PnP 精确接口打开证明新的句柄代次，关闭/复制失效，不读报告、不开生产映射，不把同宿主或对象目标作为替代归属。附加前既有句柄保持未知；若自然状态没有精确关联，不要求反复按键或重连来假装可用，需收束外部门槛。该诊断本身不是冷首用的产品方案；同日唯一120秒自然观察没有future-open，既有550次调用仍无来源，正常清理后停止此用户态路径。状态归 TODO，证据 `artifacts/hid-host-future-open-20260919/evidence.md`。

2026-09-19 来源核对见 [三键来源静态核对](../ATTRIBUTION.md#three-key-reference-static-review)：remote-bridge-hub 提供直接报告旁路参考，miaomiaozii 是整合示例；nijez/open-voice-bridge 本轮所查 main 未实现相关注入。用户随后纠正并续推：既有匹配失败不能等同三键不可实现，开发方须分别判定来源归属和精确抑制，不要求用户寻找技术方案。仅以已有源码、冻结证据和系统二进制作限定静态核对，不新增探针或重复失败实验；方案成立后仍按原授权完成实现与验收。限定 WDF 来源链、格式化及同步/异步完成契约静态核对已完成，现进入精确来源与描述符双门禁的最小生产候选实现、构建和真机验证；尚未满足验收，不能概括为外部 blocked；Microsoft 签名只约束内核候选。此纠正替代此前停止一切开发及泛化外部阻塞的结论，保留来源、安全与实机验收门禁。具体判定见 [既有证据](../artifacts/hid-gatt-access-20260919/evidence.md#static-feasibility-correction)，任务状态仍归 TODO。

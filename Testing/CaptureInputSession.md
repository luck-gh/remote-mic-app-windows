# 默认麦克风切换与恢复

用户于2026-09-16明确授权“允许受限使用，并接受外部改选时让出控制”。此功能在当前用户 Voice DOWN 准备中受限使用 IPolicyConfig; 2026-11-01 用户额外明确授权界面按钮的一次性默认输入设置, 只扩展这一手动入口。主程序保持普通权限, 不注入第三方程序, 不修改默认输出设备。

2026-10-30 用户将开关调整为两个依赖复选框: “说话时切换到所选麦克风”与“松开后恢复原麦克风”。两项关闭不切换; 仅第一项开启时, 本次成功切换后保留 Windows 默认输入; 两项开启维持临时切换。第二项在第一项关闭时禁用并取消勾选。已有启用配置仍保持临时恢复, 新字段 `keepSelected` 默认 false。

保留模式以三角色读回确认、源请求仍有效并成功清除事务记录为提交点; 此后语音结束、快捷键失败或应用退出不恢复原设备。提交前的失败、取消、部分写入继续原事务回滚。清记录期间的活进程取消仍回滚; Windows setter 无 CAS, 不承诺进程在提交与回执之间崩溃时的原子确认。

目标在三角色均已是默认且没有未处理恢复记录时, 使用无租约路径: 不激活 setter、不写新 journal、不启动周期监测、不安排结束恢复。仍核对目标有效身份和当前角色, 不用名称猜配或陈旧缓存。期间外部改选遵从新选择。输入法自行固定的麦克风不保证跟随 Windows 默认设备; 本应用遥控 PCM 的同线写入端不因此改变。

常规页面分别展示“声音写入设备”和“Windows 默认麦克风（可选）”。前者沿用上游的遥控 PCM 写入 Render 路径: VB-CABLE 选择 CABLE Input, 输入工具自行选择 CABLE Output; 不改变 Windows 默认麦克风。后者选择 CABLE Output 等 Capture 目标, 通过两个依赖复选框控制默认切换与恢复, 默认关闭; 输入法已固定目标麦克风时无需开启。

默认切换关闭时, 手选和启动恢复尊重已保存的声音写入端, 不因未使用的旧 Capture 不可用而阻止它或重新配对; 状态只验证实际 Render 身份与就绪情况。目标麦克风选择此时仅为页面草稿, 显式“设为 Windows 默认”才更改系统输入。开启自动策略时仍验证严格同线配对并保存目标, 不等于当场更改 Windows 默认输入。高级诊断保留显式配对与恢复操作。此变化不声称关闭后全产品不调用任何 Capture API: 默认值展示及既有输入设备诊断仍独立存在。

切换三角色读回后才注入目标快捷键，源UP取消迟到启动。临时模式中 BLE owner先释放快捷键，再结束音频/路由；不能在释放排队时抢先恢复其他麦克风。

Console/Multimedia可能联动，写前持久记录before/desired/mask，仅接受组内向目标收敛；第三值和组外改变使本次整体让出。normal原两角色分裂时写前明确拒绝，以免无法精确恢复。崩溃后提供可见恢复/保留，不自动覆盖。没有CAS或通知actor，同值用户操作无法识别；第三方显式设备不保证跟随默认。
